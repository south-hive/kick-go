# 알까기 룰셋과 샷 연출

## 룰셋

`web/rules.js`가 공개 룰셋의 정의를 소유한다. 기본값은 기존 규칙을 유지하는 `modern`이다.

| 기능 | classic | modern |
|---|---|---|
| 5개 돌, M자 배치, 중앙 연결쇠, 기본 충돌 | 사용 | 사용 |
| 회전 타격 | 사용 안 함 | 사용 |
| 금강불괴 | 사용 안 함 | 사용 |
| 겁쟁이 궤적과 선공 1회·후공 2회 제한 | 사용 안 함 | 사용 |

클래식은 금강불괴 선택 없이 조준으로 진입한다. 아방가드는 아직 등록하거나 노출하지 않는다. 향후 룰셋은 이 레지스트리에 추가하고, 새 물리 규칙은 `physics.js`, 판정·샷 이벤트는 `shot-engine.js`, 시각·음향 효과는 `shot-effects.js`에 구현한다. 클라이언트의 지원 룰셋 검증과 UI 선택지도 함께 갱신해야 한다.

오프라인에서 룰셋을 바꾸면 확인 후 새 경기를 시작한다. 온라인에서는 방장이 생성할 때 선택하고, 참가·관전·재접속·재대결에서 서버의 선택을 유지한다. 진행 중 변경은 지원하지 않는다. 클래식의 특수 기능은 UI를 숨길 뿐 아니라 서버에서도 거부한다.

## 확정 → 계산 → 보관 → 재생

1. 조준 중에는 기존 `Physics.predict`가 짧은 공개 궤적만 계산한다. 금강불괴 선택은 예측에 사용하지 않는다.
2. 발사를 확정하면 `AlkkagiShots.plan(stones, shot, {ruleset, id})`이 복사한 판에서 120Hz로 샷이 끝날 때까지 계산한다. 실제 판은 아직 움직이지 않는다.
3. 읽기 전용 기록에는 `frames`, 시간·순서가 있는 `events`, `result`가 들어간다. 결과에는 양쪽 잔여 돌, 떨어진 돌, 상대/아군 제거 수, 발사 돌 낙하 여부, 경기 종료·승자 등이 들어간다. 기존 서버 제한과 맞춰 최대 25초까지 계산하고, 제한에 도달하면 명시적인 `shot:limit` 이벤트를 남기고 정지시킨다.
4. `shot:prepared` 훅은 이 기록 전체를 받는다. 결과에 맞는 연출을 여기서 준비할 수 있다. 겁쟁이 사전 연출이 있는 경우에도 계산은 먼저 완료된다.
5. `Playback`은 저장한 프레임을 복사해 적용하며 이벤트를 한 번씩 전달한다. 재생 중 물리를 다시 계산하지 않는다. AI는 재생된 공개 움직임만 관찰하며, 실제 사전 계산 결과나 금강불괴 선택을 AI 판단에 전달하지 않는다.

오프라인의 `lastShot`, 온라인 서버의 `Room.lastShot`에 **가장 최근 샷 하나**를 보관한다. 다음 샷으로 교체되며 새 경기·재대결 때 제거된다. 브라우저/서버 메모리 보관이며 저장소에 영구 기록하거나 전체 경기 리플레이를 제공하지는 않는다.

## 연출 훅

`AlkkagiShots.Hooks.on(type, handler)`는 구독 해제 함수를 반환한다. `'*'`로 모든 이벤트를 관찰할 수 있다. 콜백 예외를 격리하므로 하나의 효과가 실패해도 재생과 다른 효과는 계속된다. 사전 기록은 깊게 동결되므로 연출 콜백에서 물리 결과를 바꿀 수 없다.

| 이벤트 | 의미 |
|---|---|
| `shot:prepared` | 전체 결과와 타임라인 계산 완료. 로컬 또는 권한 있는 서버 내부에서만 제공 |
| `guide:used` | 유효한 겁쟁이 샷 확정. 발사 전 연출 시작 (`tick: -1`, `time: -1.35`) |
| `shot:start` | 실제 샷 재생 시작. 겁쟁이 사전 연출 종료 |
| `impact` | 충격 위치와 세기. 소리·파동 등 기본 효과에 사용 |
| `stone:collision` | 돌끼리 충돌한 시점과 돌 ID |
| `obstacle:collision` | 중앙 연결쇠와 충돌 |
| `stone:fall` | 돌 낙하, 소속과 위치 |
| `shot:clean-miss` | 발사 돌이 돌·연결쇠와 아무 접촉 없이 판 밖으로 나간 순간 |
| `iron:hit` | 상대의 활성 금강불괴가 실제로 공격을 막은 순간 |
| `iron:clash` | 금강불괴였던 발사 돌이 상대의 활성 금강불괴를 직격해 파쇄하고 일반 충돌로 전환한 순간 |
| `protection:spent` | 금강불괴 소모. 온라인은 해당 팀과 관전자에게만 제공 |
| `shot:knockout` | 상대 돌을 하나만 제거한 샷의 낙하 시점 |
| `shot:combo-hit` | 한 샷에서 상대 돌을 여러 개 제거할 때, 탈락할 상대 돌의 첫 충돌 시점. `count`는 충돌 순서대로 1부터 증가 |
| `shot:multi-knockout` | 샷 종료 시 상대 돌 2개 이상 제거한 결과 요약 |
| `shot:self-knockout` | 샷 종료 시 발사 돌도 탈락 |
| `shot:limit` | 시뮬레이션 시간 상한에 도달 |
| `shot:end` | 샷 종료와 결과 요약 |
| `match:end` | 최종 승자 또는 무승부 |
| `shot:resume` | 온라인 입장·재접속 시 현재 샷 상태 복원. 과거 효과를 재생하지 않고 진행 중인 겁쟁이 카드만 남은 시간으로 복원 |
| `match:start`, `turn:start` | 게임 화면의 경기 초기화·조준 차례 진입 |

기본 효과는 `web/shot-effects.js`에 분리했다. 기존 타격음·낙하 효과와 작은 충돌 파동을 연결하고, 캐릭터별 멘트·효과와 겁쟁이 카드는 `character:reaction`을 구독해 표시한다. 움직임 감소 설정에서는 충돌 파동을 표시하지 않는다. 새 효과를 추가할 때 보드·물리 코드를 수정할 필요가 없다.

브라우저에서는 `window.alkkagiEffects`, 서버에서는 `room.hooks`를 사용한다. 예를 들어 오프라인/서버에서 연출을 준비하고 실제 충돌 시 실행하려면:

```js
let plannedResult;
const stopPreparing = hooks.on('shot:prepared', record => {
  plannedResult = record.result;
  // 결과에 맞는 연출 자원을 준비한다.
});
const stopImpact = hooks.on('stone:collision', event => {
  // event.time, event.x, event.y, event.stones에 효과를 연결한다.
});
// 화면이나 효과를 폐기할 때:
stopPreparing();
stopImpact();
```

## 온라인 공개 범위

전체 기록은 서버에만 둔다. `shotPlayback` 메시지는 샷 ID, 현재 틱, 시작·종료 여부, 진행 중인 겁쟁이 카드의 남은 시간, **이미 지나간 공개 이벤트**를 제공하고 최종 결과는 재생이 끝난 뒤에만 제공한다. 미래의 프레임·이벤트·샷 입력·상대 금강불괴 상태는 보내지 않는다. 결과를 활용한 온라인 사전 연출은 서버의 `shot:prepared`에서 결정하되 공개할 연출 메시지는 별도로 설계해야 한다.

서버는 마지막 샷의 경과 이벤트를 누적 전송하고, 클라이언트는 `(샷 ID, sequence)`로 중복을 제거한다. 재접속 첫 상태는 커서만 복구해 이미 지난 타격음이나 낙하 연출을 반복하지 않는다. 이후 이벤트부터 정상적으로 재생한다. 겁쟁이 사전 연출 중이라면 `shot:resume`에서 현재 카드만 복원하고 시작 효과음이나 이전 멘트는 반복하지 않는다.

웹 화면과 Node 서버를 함께 배포해야 한다. 새 클라이언트는 룰셋·샷 재생 정보가 없는 구버전 서버를 감지하면 업데이트를 안내한다. Android WebView의 정적 파일 허용 목록에도 새 모듈을 포함했다.


## 상황 판별 기준

- `shot:clean-miss`: 발사 돌의 낙하 순간에 발생한다. 상대 돌뿐 아니라 아군 돌·연결쇠도 접촉으로 센다. 매우 느린 접촉이나 겹침 해소로 밀려난 경우도 제외한다. 충돌 없이 멈추기만 한 샷에는 발생하지 않는다.
- `shot:combo-hit`: 사전 계산 결과 상대 돌을 2개 이상 제거하는 샷이면, 실제로 탈락할 상대 돌의 첫 충돌 틱에 발생한다. `count`는 해당 돌들의 첫 충돌 순서이며, 살아남는 돌과 아군 탈락은 제외한다. 숫자는 대사 대기열을 거치지 않고 `1타 2타 3타`로 누적하며, 샷 종료 0.9초 후 함께 지운다. 다음 샷·새 경기에는 즉시 초기화한다. 한 개만 제거하는 샷은 `shot:knockout`이고 기본 캐릭터의 숫자 멘트는 없다.
- `shot:multi-knockout`: 한 샷으로 **상대 돌 2개 이상**을 제거했을 때 샷 종료에 한 번 발생한다. `count`는 제거한 상대 돌 수이며, 아군 탈락 수는 `shot:end.result.ownRemoved`로 별도 확인한다.
- `iron:hit`: 사람의 실제 인지 여부를 추측하지 않는다. 상대의 숨겨진 금강불괴가 해당 충돌에서 실제로 방어를 발동했는지를 판정한다. 아군 충돌이나 이미 소진된 금강불괴에는 발생하지 않는다.
- `iron:clash`: 발사 직전에 활성 금강불괴였던 돌 자체가 상대의 활성 금강불괴를 향해 직접 충돌하면 발동한다. 상대의 버티기·반사를 무효화하고 양쪽 보호를 소모한 뒤 **일반 돌과 같은 탄성 충돌·회전·마찰**을 적용한다. 추가 힘이나 강제 탈락은 없다. 마지막 금강불괴 두 개가 남은 경우에도 같다. 발사한 돌의 파쇄 자격은 `ironShot`으로 첫 접촉 전까지만 기억한다. 첫 접촉이 상대의 활성 금강불괴 직격이면 파쇄하고, 연결쇠 또는 다른 돌에 먼저 스치거나 맞히면 자격을 소모한다. 소리가 나지 않는 약한 접촉도 포함한다. 정지·낙하 시에도 지운다. 다른 돌에 이력을 전달하지 않는다. 이 필드는 모든 온라인 참가자·관전자 상태에서 제거한다. 같은 충돌에서 `iron:hit`과 중복 발생하지 않는다.
- 두 금강불괴 이벤트는 `attacker`, `defender` 돌 ID와 `actorTeam`, `targetTeam`, 충돌 위치를 제공한다. 온라인에서는 실제 충돌에 도달한 뒤 양쪽과 관전자에게 전달한다. 따라서 `iron:clash` 연출은 충돌 시점에 **이미 소모된 발사 돌의 금강불괴 이력**을 드러낸다. 발사 전 선택이나 미래 충돌은 공개하지 않는다.
- `guide:used`: 버튼을 켜는 순간이 아니라, 검증을 통과하고 사용 횟수를 소비하는 발사 확정 시점에 발생한다. 취소·거부된 샷은 발생시키지 않는다. `Playback.prepare()`가 한 번 전달하고 `Playback.start()`부터 물리를 재생한다. 연출 종류와 무관하게 기존 1.35초 대기 규칙을 유지한다.

## 캐릭터 프리셋 작성

`web/characters.js`의 레지스트리는 캐릭터의 **이벤트별 데이터**를 보관한다. 현재 `default`는 기본 캐릭터다. 겁쟁이 샷에 “겁쟁이 녀석!”, 금강불괴 파쇄에 “파쇄!”, 상대의 무충돌 이탈에 “집중하세요.”를 말한다. 한 샷에서 상대 돌을 여러 개 내보낼 때는 탈락할 돌의 첫 충돌마다 “1타”, “2타”, “3타”…를 누적 표시한다. 다음 샷은 다시 1타부터 세고 아군 탈락은 세지 않는다. 마지막 돌도 숫자로 부르며 “막타” 멘트는 없다. 초상화나 다른 캐릭터의 선택 화면은 아직 추가하지 않았다.

`responses[이벤트명]` 아래에 `actor`(행동한 쪽), `target`(상대/피격 쪽), `other` 반응을 넣는다. 한 이벤트에서 각자 자기 프리셋의 해당 역할을 사용한다. 여러 멘트 중 하나를 샷 이벤트 ID·팀·프리셋 ID로 결정하므로 참가자와 관전자가 같은 멘트를 본다. `{name}`, `{actor}`, `{target}`, `{count}`를 문자열 안에서 사용할 수 있다. 멘트는 HTML로 해석하지 않는다.

```js
// 실제 프리셋은 characters.js에 등록하여 서버와 모든 화면에 같이 배포한다.
AlkkagiCharacters.register({
  id: 'sample',
  name: '캐릭터 이름',
  responses: {
    'shot:clean-miss': {
      actor: { lines: ['어디로 간 거지?'], effects: [] },
      target: { lines: ['이번엔 내가 살았네.'], effects: [] },
    },
    'iron:hit': {
      actor: { lines: ['금강불괴였어?!'], effects: [{ type: 'ring', color: '#7cf4d8' }] },
      target: { lines: ['쉽게 밀리진 않아.'], effects: [] },
    },
    'iron:clash': {
      actor: { lines: ['파쇄!'], effects: [{ type: 'shout' }], duration: 900 },
    },
    'shot:combo-hit': {
      actor: { lines: ['{count}타'], effects: [{ type: 'shout' }], duration: 650 },
    },
    'guide:used': {
      actor: { lines: ['계산은 끝났어.'], effects: [{ type: 'guide-cue' }] },
    },
  },
});
```

등록하지 않은 이벤트는 공통 프리셋을 따른다. 특정 이벤트에 아무 반응도 하지 않으려면 해당 이벤트를 `{}`로 등록한다. 이벤트 하나를 정의하면 그 이벤트의 역할 묶음 전체를 교체한다. `lines: []`로 효과만 사용할 수도 있다. 일반 멘트는 팀별 큐로 순서대로 표시하며 `duration`(밀리초, 기본 1800, 최대 10000)을 지정할 수 있다. 큐는 팀당 8개까지 보관하고 경기 초기화·연결 종료 시 비운다.

연결 구조는 다음과 같다.

```text
물리 접촉 → 상황 이벤트 → 캐릭터 프리셋의 actor/target 반응
                         → character:reaction → 말풍선·화면 효과
```

브라우저의 `window.alkkagiCharacters.assign(team, presetId)`로 오프라인 팀별 프리셋을 지정할 수 있다. 샷 재생 중이나 온라인에서는 이 개발용 API로 변경할 수 없다. 온라인에서는 `create`/`join` 요청의 `characterId`로 본인 프리셋을 지정한다. 서버가 허용 목록을 검증하고, 공개 상태의 `characters[0..1]`로 동기화한다. 미지정이면 `default`이며 재접속·재대결에서도 유지한다. 상대의 프리셋을 덮어쓰는 요청은 없다.

렌더러는 기본 `ring`, `caption`, `shout`, `guide-cue` 효과를 제공한다. `shout`는 말하는 사람 이름과 큰 외침을 보여준다. `caption`·`shout`는 최대 16개를 순서대로 재생하므로 한 프레임이나 온라인 패킷에서 여러 낙하가 발생해도 1타·2타가 덮어써지지 않는다. 경기 초기화 시 큐를 비운다. 움직임 감소 설정에서는 외침의 확대 애니메이션을 끈다. 새 효과는 물리 코드 수정 없이 등록한다.

```js
const unregister = window.alkkagiPresentation.registerEffect('my-effect', (reaction, effect) => {
  // reaction.team, reaction.role, reaction.event.x/y, effect의 설정값으로 표현한다.
});
// 프리셋: effects: [{ type: 'my-effect', ...설정값 }]
// 효과를 폐기할 때 unregister();
```

`AlkkagiCharacters.bind(hooks, getPlayers)`는 이벤트를 반응으로 변환하는 구독 해제 함수를 반환한다. 연출 코드가 실패해도 샷 결과나 다음 효과를 바꾸지 않으며, 재접속은 현재 겁쟁이 카드 외의 과거 캐릭터 반응을 다시 실행하지 않는다.

기본 캐릭터는 `shot:multi-knockout` 요약에는 별도 멘트를 하지 않는다. 각 충돌의 `shot:combo-hit`에서 이미 타수를 누적했기 때문에 종료 시 중복 연출을 하지 않기 위해서다.

타수 UI는 캐릭터와 관계없이 숫자를 즉시 누적한다. `shot:combo-hit` 캐릭터 반응은 대사/외침 큐에 넣지 않는다. 재접속 중인 샷의 기존 타수는 소리나 충격 없이 복구하고, 끝난 샷의 타수는 재생하지 않는다.
